# PRX data availability and acknowledgments

APS requires a Data Availability Statement and references to public supporting data
and software. Its guidelines encourage a versioned repository/archive and prefer
persistent identifiers. They do not say that a link to a moving GitHub branch alone
establishes numerical reproducibility.

For the manuscript, place the acknowledgments and the availability statement after
the conclusion and before the bibliography, consistent with the journal's handling
of the statement after acknowledgments. Supply the same availability information
in the submission form. Preserve the archived code and data references in the
bibliography rather than embedding only an unversioned URL in prose.

Use `data_availability_current_draft.tex` while deposition is pending. Use
`data_availability_after_release.tex` only after the listed assets exist publicly,
the identifiers have been filled, and the exact run versions have been checked.
The template does not authorize claiming the new package generated old results.

Keep funding and acknowledgment entries blank until confirmed. Do not copy funding
from ParaEMT's README; that support concerns the external simulator, not necessarily
this study. Do not claim acknowledgments on behalf of coauthors without confirmation.

PRX also requires disclosure of substantive uses of AI tools. Because this task
involves software restructuring and numerical-code changes, review that policy and
describe actual assistance and author verification where applicable. A possible
sentence to adapt after review is: "An AI-assisted tool was used to help refactor
and document portions of the software; the authors reviewed and validated the
released implementation." Do not include a validation claim until validation has
actually been performed, and do not use the sentence to substitute for that work.
